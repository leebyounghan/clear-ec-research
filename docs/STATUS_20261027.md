## Deployment risks (open)

- Phase 1 container is `pytorch 2.1.2 + CUDA 12.1`; the research venv is `torch 2.11 + CUDA 13.0`.
  The Phase 2 container must be rebuilt on a CUDA 12.x base and tested end to end.
- Recipe A processes 20,336 tokens per image. H200 dry run under a 15 GiB allocator cap with flash/cuDNN
  SDPA disabled (`results/t4_dry_run_20261027/result.json`): fp16 single view **0.99 GiB peak, 0.138 s/image**
  (four-flip TTA 0.551 s/image); fp32 1.07 GiB. With the math-only SDPA backend the 18.5 GiB attention
  matrix **OOMs** — the container must run PyTorch's memory-efficient SDPA kernel on sm75 and assert it at
  start-up. Precision drift on 200 fold4 images: fp16 vs fp32 max relative deviation 0.07% (MAPE −0.0006pp),
  bf16 (training dtype) vs fp32 0.9% (MAPE +0.0025pp); fp16 inference is safe. Rough T4 bound at 15–25×
  slower than H200: ≲3.5 s per image single view, ≲14 s with TTA.
- TTA preview on the same 200 images (bf16): 9.052 → 9.013 (−0.039pp); the OOF-wide gate is still pending.
- Hidden evaluator behaviour on zero ground truth and per-case rounding is unverified.
