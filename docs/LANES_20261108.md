## How to work

- Simple logic. Go for the biggest lever on your metric, run it, read it, and push whatever moves.
- Do not drop a direction after one failed try: try at least three clearly different versions first. When something moves your metric, keep pushing it (longer, bigger, more seeds, more folds) before polishing details.
- You may build a model only for your metric: single-target loss, its own input size or crop, its own backbone, its own post-processing. The final submission may use a different model per metric.
- Use anything already built: stored OOF predictions of the best pipeline, the deployed detectors, graph features, the external Topcon point set (approved), the 25 expert-marker frames for quick checks.
- "Closed" below means closed as tested. The same test on the same inputs is not worth rerunning; a clearly different version is fine.

## Bottleneck first, time boxes, no detail chasing (PI approved, 2026-11-08 evening)

The PI approved bottleneck ordering and time boxes and asked for no detail chasing, no bias and no statistics. The numbers below (12 GPU-h, 09:00, the freeze box) are the coordinator's implementation, not the PI's words.

Gap to V14 per metric, if submission 1's test-minus-OOF gaps repeat: CV about 0.12, CD about 0.09, HEX about 0.04. HEX on test was also 0.40 worse than OOF; BRIEF lines 84-87 hold the analyses done so far.

- **Order your queue by how much of your gap a job can close.** Big levers first: a new model family, a new input signal, a cross-lane member. Small polish goes last.
- **Time box every direction:** at most about 12 GPU-hours (or about 4 CPU-hours) to show a gain on folds 0 and 4, across its three versions. A direction that moves gets more time. One that doesn't is stopped when the box runs out. Write continue or stop for each open direction once a day, at 09:00 Eastern, in `REPORT.md`.
- **Freeze box:** start a new GPU direction only if its five folds can finish before 11-11 18:00 Eastern.
- **No detail chasing.** Spend time on ideas with a plain reason: more cells read, cleaner boundaries, stronger image features, a different model. Don't sweep knobs such as thresholds, epoch counts or alpha grids in fine steps. Pick a sensible value once and move on.
- **No shortcuts that won't hold on test.** Don't let a model or a correction key on image source or ID format, file names, donor or fold identity, or a handful of odd rows. Make no per-source or per-fold choices.
- **Kept gains stay kept.** Steps and members already kept under "Reading results" stay, however small. "No detail chasing" decides where new time goes; it is not a reason to remove a kept gain. (Corrected 2026-11-09: the coordinator had added "prefer simple corrections over many small steps" here, which was not the PI's rule.)
- **No statistics work.** One point estimate per try is enough. Don't compute CIs or significance tests.
- **Check the knowledge graph before a new direction** (PI request 2026-11-09). The KG lives in `kg/` in this repo. The path has a space, so quote it.
  1. Run `/usr/bin/python3 "<repo>/kg/scripts/kg_query.py" check <words>` and `closed --metric <CD|CV|HEX>`, and read the notes behind the hits.
  2. Do a quick web or literature search for the idea.
  3. Write the KG ids and paper links you found in the RESULTS.tsv note of the new direction's first row.
  Lanes don't edit the KG; the coordinator re-ingests lane rows daily.
- **One recipe across folds.** The same members, seeds and settings on every fold. A stack that uses a member on some folds only is not a five-fold number.

## Facts per lane

CD
- CD = 1e6 / integer mean cell area. Label / expert-marker density 0.97-1.43, near 1 on clean sets.
- Error 7.11 on old-format IDs, 5.50 on new ones; the image tells the two sources apart (AUC 0.998).
- CD error follows detector count and confidence; half of the worst decile is frames with no readable cells. 25 rows with impossible-looking labels are worth -0.18 and cannot be predicted.
- Closed: CD density channel; CD from point-map grid features; canonical cell-size zoom of the regressor input.

CV
- 78 distinct label values, step 0.01. Device CV is about twice the Voronoi area CV of the same markers.
- Best pipeline: r 0.686; predictions span 66 % of the label spread; the two outer deciles hold about a third of the error. Fellow-eye labels correlate 0.43.
- Expert markers give CV r 0.89, MAPE 8.8 (25 frames). Detector misses merge cells and ruin area CV; neighbour-distance CV degrades less.
- Closed: consensus Voronoi CV; CV-only graph loss; tail pooling; disagreement-based calibration; simple CV estimators; graph node image tokens.

HEX
- hex6 of expert markers is within 1-2 % of the label on clean sets. The hex6 detector ensemble saturates at about 9 detectors.
- Submission 1 HEX on test was 0.40 worse than OOF (94th percentile of OOF draws): prefer robust, simple corrections.
- Worst HEX frames are clearer than matched controls; most look like label scatter.
- Closed: hex6 checkpoint selection by marker r; graph repair; watershed graphs.

Backbone
- Every recipe A change tested end to end (strong-view SSL, measured augmentation, RoPE scale) came back to the same solution (residual r 0.98-0.99). Other families were worse alone (+0.27 to +0.59); DINOv3 B/16 added -0.0166 (CI -0.028, -0.005).
- Never tried under recipe A: drop path, layer-wise LR decay, EMA or SWA, mixup or cutmix, distillation from the ensemble, ViT-L on the whole frame. Encoder LR x5 overfit (train 8.30 to 7.26, validation 9.11 to 9.44).
- Label fraction 50 % on fold 0: 9.165 against 9.081, so halving the labels costs only about 0.08.
- Closed: strong-view SSL (crop 544, broad optics), measured noise and optics augmentation, DINOv2 B/14, ConvNeXt base, DINOv3 stride 8 (fold 0), within-donor training, donor memory.
