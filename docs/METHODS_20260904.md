## Four predeclared recipes

All recipes start from the original CPSAM checkpoint, use seed42, the same five slide-group folds (fold seed2026), train batch48, encoder LR1e-5, head/norm LR1e-3, AdamW weight decay1e-4, BF16, and gradient clipping1. Each runs 35 epochs instead of the historical 25. LR has a 200-update warmup and cosine decay to 5% of the starting LR. There are 149 updates/epoch and 5,215 updates/run. Best checkpoint is selected by five-view validation; final comparison always uses C5 × D8 (40 views).

| Recipe | Change beyond shared 35-epoch cosine schedule | Hypothesis |
|---|---|---|
| cosine35 | Existing standardized-log L1, one random native256 crop | A longer low-LR tail might converge better; control for the other three recipes |
| metric35 | 0.5 × standardized-log L1 + 0.5 × MAPE/0.2 | Better match the relative-error evaluation objective without dropping the stabilizing original loss |
| predbag2_35 | Two independent random native256 crops; average per-crop **head outputs** before loss | Reduce the mismatch between single-crop supervision and multi-crop prediction averaging |
| sam35 | SAM global-L2 radius0.02 with AdamW descent | Favor locally stable solutions and potentially reduce sensitivity to label variation |

The MAPE term is `mean(abs(expm1((z_pred - z_target) * log_scale)))`: it equals physical-space relative error against the training targets. The common 0.2 divisor is fixed in advance, not fitted and not a per-metric weighting. No exponent clipping is used; nonfinite values terminate the job explicitly.

SAM computes two backward passes on the SAME augmented inputs and replays dropout RNG for the second pass. Parameter restoration uses exact saved copies even on exceptions; only the second gradient drives AdamW. This is an AdamW-based SAM recipe, not a claim to reproduce any published benchmark result.

The prediction bag is not the previously unsuccessful feature-mean/std MIL or global-view attention model. Both crops pass independently through the same head; predictions are averaged in standardized-log space, exactly as the spatial/dihedral inference aggregation. It does not claim to solve arbitrary raw full-frame context loss. Inference architecture/state keys remain compatible with the mean-pooling baseline.

No new DINO/JEPA pretraining is included in this finite queue: the earlier JEPA OOF result was not better after the optimizer correction, and these four experiments target specific remaining optimization/supervision gaps with a smaller turnaround. This is a prioritization decision, not evidence that another representation could not help.

## Evidence behind the hypotheses

- [SAM original paper](https://arxiv.org/abs/2010.01412) motivates minimizing loss in a parameter neighborhood and reports generalization/noise-robustness results on its benchmarks. CLEAR-EC benefit is unproven until this experiment finishes.
- [MAPE regression analysis](https://arxiv.org/abs/1605.02541) establishes its relation to weighted MAE; matching a relative-error objective is a testable alternative to standardized-log loss, not guaranteed to win.
- Longer cosine training and prediction-level bag averaging are engineering hypotheses based on this repository's training/inference mismatch, not claims established by those papers.

## Finite queue and fixed advancement rule

1. Four independent GPU smoke runs (one update, eight validation images, separate smoke output) must pass, along with unit tests.
2. Run four recipes × folds0/1 = **eight full jobs**, one per GPU.
3. Evaluate uncalibrated standalone results against fixed seed42 and a fixed four-model equal-weight ensemble against the existing three-seed ensemble. The latter is 75% old ensemble + 25% new model in physical prediction space; no fitted ensemble weights.
4. A recipe passes if standalone aggregate delta ≤ −0.02 and worst fold delta ≤ +0.05, OR ensemble aggregate delta ≤ −0.01 and worst fold delta ≤ +0.02. Negative is better. Rank passing recipes by ensemble delta, then standalone delta, then name; keep **at most two**.
5. The pod controller immediately schedules folds2/3/4 for those recipes, **at most six more jobs**. No local app wakeup is needed to advance.
6. Automatically compare confirmation folds separately, then all five folds. A blend confirmation flag requires negative aggregate delta on folds2/3/4, wins on at least two of those three, and five-fold ensemble improvement ≥0.01. This flag requires review; it does not overwrite the final candidate or trigger submission.

**Maximum 14 full training jobs**, plus four short smoke tests. A recipe can help standalone without helping the existing ensemble; both are reported. All folds were used in historical development and each fold selects its own checkpoint. The three confirmation folds are held out from THIS recipe-screen decision only, not untouched test data. Exploratory calibration is reported after five folds, never used as the screening gate. Bootstrap or calibrated gains would still need this selection caveat.

The faster screen jobs can finish before SAM/two-crop jobs; GPUs may then be idle until the complete, fixed screen decision. They are not occupied with unapproved duplicate training merely to show utilization. The selected six-job confirmation wave uses up to six GPUs. Finite job completion releases GPUs but never stops the pod.
