# tier p2 (더 빠른 p) — 아침 절차 (배포 레인, 2026-11-14 05:41 EST)

오늘 밤에는 팟에서 준비와 동등성 시험만 했습니다. 박스 전송·빌드·업로드는 하지 않았고, 기존 p·t3 폴더/매니페스트/아카이브는 건드리지 않았습니다.

## 무엇이 다른가
- tier p에서 DINOv3-B s47 CD 절반을 뺐습니다. CD 상수는 CD 레인이 같은 절차로 다시 맞췄습니다(`freeze_cd_params_p2_20261114.json`). strict CD는 6.1723으로, p의 6.1737보다 0.0014 낮습니다.
- 같은 파일을 한 잡에서 여러 번 읽던 4곳을 한 번만 읽게 했습니다. 각각 스위치로 켜고 끄며, p2 이미지에서는 넷 다 켜져 있습니다.
- CV와 HEX 출력은 p와 같고, CD만 조금 바뀝니다.
- **팟 동등성 결과** (스모크 5프레임, fp16b1 모드, GPU 0/3):
  - 스위치를 하나씩 켜도, 넷 다 켜도 CD는 p와 비트 단위로 같았습니다.
  - CV·HEX의 최대 차이는 5.1e-9(상대 1.1e-8)로, 1e-6 기준 안입니다.
  - 이 크기는 스위치를 모두 끈 p2 코드와 p 사이의 차이(CV 2.8e-9, HEX 1.2e-9)와 같습니다. GPU `index_add_`의 비결정성 때문이며, p도 돌릴 때마다 이만큼 달라집니다.
  - p2 매니페스트에서는 CD가 프레임당 -2.60 ~ +0.85 바뀝니다(최대 상대 0.093%). CV·HEX는 같은 노이즈 범위 안입니다(최대 1.3e-9).
- **메모리:** 스위치를 켜면 첫 잡의 최대 RSS가 5.1 GB에서 5.7 GB로 늘어납니다(캐시 최대 2.4 GB). 테스트 컨테이너 한도 16g 안입니다.
